## 一、登录与角色

访问 `https://你的域名`，用后台账号登录。左侧菜单按角色可见：

| 角色 | 可见菜单 |
| ---- | -------- |
| 超级管理员 | 全部 |
| 景区管理员 | 数据看板、核销中心、景区管理、票务管理、订单管理 |
| 检票员 | 核销中心（核销台 / 核销记录） |
| 财务 | 数据看板、订单管理（含退款审核） |
| 运维 | 数据看板、闸机管理 |
| 领导 | 数据看板 |

**首次登录请立即修改密码**（右上角头像 → 修改密码）。超管默认账号 `admin / admin123` 仅用于初始化。

## 二、景区管理员：票务配置

> ⚠️ **配置有先后顺序**，跳步会导致小程序端看不到票或无法下单：
> **景区 → 时段 → 票种 → 库存**（价格日历可选）

### 2.1 景区信息
「景区管理 → 景区信息」填名称、地址、开放时间、**最大承载量**。

- **新增景区时可以勾选「一键生成默认时段与票种」**（默认开启）：会一并建好 4 个时段
  （08:00-17:00，每两小时一场）、3 个票种（成人全票 ¥120 / 优待票 ¥60 / 四季家庭年卡 ¥388），
  并为**按人计价**的两个票种生成未来 7 天、每时段 100 张的库存 —— 建完就能直接卖票，
  不用再去「库存管理」补。生成天数与每时段张数可在同一处改。
- 关掉这个开关就是「全部手动配置」；也可以先建个空景区，之后在景区列表调
  `POST /api/admin/scenic/areas/:id/defaults` 补上（**幂等**，已存在的时段/票种不会重复建）。
- 注意：**四季家庭年卡按「张」计价，不分时入园**，所以不会给它生成分时库存，
  小程序上也会提示「暂不支持在线预约」。
- **景区的两张图**（都在景区表单里上传，jpeg / png / webp，5MB 内）：
  - **景区封面**（建议 16:9）：小程序里的**景点列表卡**与首页「推荐景点」卡
  - **购票页缩略图**（建议 1:1 方图）：小程序购票页头卡那张小图；不传则回落到封面

  要清空某一张，点该字段的「清除」再保存（清空会按 `null` 提交 —— 传空字符串会被
  后端当成「没改」）。一张都不传时小程序用内置示意图占位。存的是相对路径，
  换服务器地址不用重新上传。
- **首页轮播图不在这里** —— 它有自己的页面：「内容管理 → **首页轮播图**」（见 2.7）。

- **景点分类**（主景区 / 自然风光 / 历史人文 / 索道缆车 / 夜游演艺）决定这个景点在小程序
  「景点选择与预约」页归到哪个筛选标签下。**留空也有用** —— 未分类的景点只会出现在「全部景点」里，
  不会出现在任何具体分类下；如果用户反馈「某个分类下没有景点」，先来这里看分类设了没有。
- 景区**一张图都不传**时，小程序端用内置占位图（景点卡按序号轮换设计稿那 4 张示意图）。

最大承载量是承载率预警的计算基准：在园人数达到该值的 **80% / 90% / 100%** 时会自动分级告警。
**这三档阈值本身也可以在「系统管理 → 参数配置 → capacity_alarm」里改**（见 2.6），
任务每 60 秒检查一次，改完最多 1 分钟生效。

### 2.2 分时时段
「票务管理 → 时段管理」配置入园时段，如 `08:00-10:00`、`10:00-12:00`。

- 名称建议带时间段（如「上午场 08:00-10:00」），方便检票员与游客对照
- 排序值决定小程序端展示顺序
- **核销时有时间容差**：允许提前 60 分钟到、晚 60 分钟入园，超出会提示「未到/已超过入园时段」

### 2.3 票种
「票务管理 → 票种管理」新建票种，需要设置：

| 字段 | 说明 |
| ---- | ---- |
| 票种名称 | 如「成人票」「儿童票」 |
| 基础价 | 单位**元**，系统内部按「分」存储，不会出现浮点误差 |
| 是否实名 | 选「是」时游客下单必须填写身份证 |
| 限购规则 | 单笔限购 / 每人每日 / **每证每日**（防黄牛关键项，默认每证每日 1 张） |
| 退改规则 | 提前 N 天免手续费、当日手续费率、过期是否可退 |

### 2.4 价格日历（节假日调价）
「票务管理 → 价格日历」为特定日期设置不同于基础价的票价。

**没有特殊价记录的日期，自动使用票种基础价** —— 所以平时不用逐日配置，只在节假日调价即可。

### 2.5 库存（最关键的日常操作）
「票务管理 → 库存管理」：

1. **批量生成库存**：选择日期范围（如未来 30 天）+ 每个时段库存数 → 提交
   - **已有记录不会被覆盖**，只补充缺失的日期/时段 → 可以放心重复执行
   - 已售出与已锁定的数量始终保留
2. **调整库存**：对某一天某个时段单独增减（如临时加放 50 张）
   - 调整后总库存**不得低于「已售 + 已锁定」**，否则会被拒绝
   - 每次调整都会写入日志（谁、何时、调了多少、原因）
3. 列表中的**剩余**列：绿色充足、黄色紧张（低于 20%）、红色售罄

**建议**：至少提前一个月生成库存；节假日高峰前检查余票并预留调整空间。

### 2.6 参数配置（平台信息与全局规则）
「系统管理 → 参数配置」有四项**带表单**的配置（每项改完立即生效，承载量预警最多 1 分钟）：

| 配置键 | 改什么 | 生效点 |
| --- | --- | --- |
| `platform` | **平台名称、英文名、副标题、平台 Logo（可直接上传，建议 1:1 方图）**、客服电话、ICP 备案号、版权信息、产品名、版本号。Logo 留空 = 用设计稿那个青绿渐变方块；填的路径指不到图（填错/文件被删）也会自动退回方块，不会出现空白 | 小程序顶栏、凭证水印、个人中心页脚；**改完重启小程序即见**，不用发版。页脚 =「{平台名称}{产品名} {版本号}」，所以**版本号要自带 V**（填 `V1.2.0`），产品名默认「智慧文旅」 |
| `reservation` | 支付超时（分钟）、超时是否自动取消 | 下单时的 `payDeadline`，以及微信预支付单的失效时间（两者同源，避免「我们的截止时间还没到、微信单已过期」） |
| `capacity_alarm` | 承载量三档阈值（在园率 %） | 定时任务的承载量分级告警。**三档须递增**，前端会拦 |
| `refund` | 提前多少天免手续费、窗口内手续费率、过期是否可退 | 退款手续费计算。**这是全局兜底，票种自身设了规则时按字段覆盖它** |

- 其它配置键（后续新增的）会回落到 JSON 编辑器，照旧手写 JSON 对象即可。
- 「平台名称」只影响**运行时**界面。小程序的 `pages.json` / `manifest.json` / 页面标题是**构建期**产物，
  换品牌名时仍需改这三处并重新构建。
- 本页目前**仅超级管理员**可见（菜单与 `config:update` 权限都只给了 `super`）。要让运营也能改平台名，
  需在「系统管理 → 角色权限」给对应角色加上 `config:update`。

### 2.7 首页轮播图（内容管理 → 首页轮播图）

小程序首页顶部那条轮播**由这一页单独维护**，与景点解耦 —— 加一张、换一张、调顺序、
临时下掉一张，都只在这里改，不用去动景区档案。

| 操作 | 说明 |
| --- | --- |
| 新增 / 编辑 | 上传图片（建议 21:9 宽图，5MB 内） |
| **跳转景点** | 选了景点：那一屏显示**该景点的名字与实时在园率**，游客点了进它的购票页；不选：显示下面填的标题/副标题，且**不可点**（适合放免票周、活动预告这类公告图） |
| 标题 / 副标题 | **只在没选跳转景点时显示**（选了景点时屏上显示的是景点名，填了也不显示 —— 列表里会标注出来） |
| 上移 / 下移 | 换顺序。换完会把整组按新顺序重排（`10/20/30…`），不用手填数字 |
| 启用 / 停用 | 停用后小程序立刻不再展示，后台仍留着（节假日临时下掉用这个，不要删） |
| 排序 | 数字小的在前；也可以直接用上移/下移 |

- **一张都不配时**，首页会**回落到「按景点生成轮播」**（各景点封面轮换）—— 所以清空这一页不会让首页开天窗。
- 跳转的景点被**关闭/删除**后，那一屏会自动退化成「只展示图」（不会显示一个不存在的景点名，也不会跳到空页面）。
- 图片存的是相对路径，换服务器地址不用重新上传。

## 三、检票员：核销操作

「核销中心 → 核销台」是日常主界面。

### 3.1 扫码核销（推荐）
1. 确认方向（**入园** / 出园）—— 默认入园
2. 让游客打开小程序订单页的动态二维码
3. 用扫码枪扫描，或手动输入凭证后按回车
4. 看结果卡片：
   - **绿色大卡片** = 核销成功，请通行（显示游客姓名、剩余可入园人数、开闸指令号）
   - **红色大卡片** = 拒绝，原因见下方对照表

> 动态二维码**每 60 秒自动刷新**，截图会在 1 分钟后失效。如果提示「凭证已过期」，请游客下拉刷新页面重新出示。

### 3.2 手动核销（游客手机没电、二维码扫不出）
切到「手动核销」页签，输入**订单号**（及证件后四位可精确到人）。

订单号在游客小程序订单详情里，格式如 `20261008190849381960`。

### 3.3 失败原因对照表

| 提示 | 含义 | 处理方式 |
| ---- | ---- | -------- |
| 凭证已过期 | 二维码超过 60 秒 | 请游客下拉刷新小程序页面 |
| 凭证无效 | 二维码不属于本系统 | 核对是否扫错码；请游客出示小程序内二维码 |
| 订单未支付 | 游客下单后未完成付款 | 引导游客先完成支付 |
| 非预约日期 | 预约的不是今天 | 核对游客预约日期；当天票只能当天用 |
| 未到入园时段 / 已超过入园时段 | 不在预约时段（含 60 分钟容差） | 请游客在对应时段前来，或改签 |
| 该票已核销 | **重复出示** | ⚠️ 注意防范：同一张票再次出示通常意味着二维码被转发或截图共用 |
| 证件已被限制通行 | 黑名单 | 联系景区管理员/安保核实 |
| 闸机权限不符 | 闸机方向与通行方向不符 | 引导游客走对应通道 |
| 该闸机不放行此时段 / 此票种 | 这台闸机配了通行规则（A-044） | 按提示引导游客走对应通道；若规则配错了，管理员在「闸机管理 → 闸机设备 → 编辑」里改 |

### 3.4 核销记录
「核销中心 → 核销记录」按渠道和日期查询，可导出 CSV。**核销记录只增不改**，一人一票只能核销一次。

### 3.5 多人订单
一个订单多人时，**每扫一次核销一位游客**。结果卡片会显示「剩余可入园人数」，剩余为 0 表示该订单已全部核销。

## 四、财务：退款、对账与报表

### 4.1 退款审核
「订单管理 → 退款审核」：

1. 默认展示「待审核」
2. 核对退款单：申请金额、手续费、**实退金额**
3. 点「审核」→ 选择通过/拒绝 → 填写备注
   - **拒绝时备注必填**（会展示给申请人）
   - **通过前请二次确认**：通过后会调用微信支付退款接口，**原路退回且不可撤销**
4. 退款成功后订单状态变为「已退款」，库存自动回流

手续费按票种的退改规则自动计算（提前 N 天免手续费、当日按比例扣、过期不可退）。

### 4.2 三方对账
「运维 → 三方对账」：

- 系统**每天 08:00 自动核对前一日**：订单 ↔ 支付流水 ↔ 退款 三方数据
- 「无差异」= 三方一致；「存在差异」需点「查看差异」看明细，分三类：
  - **缺支付流水**：订单显示已支付但无支付记录（通常是回调丢失，查单补偿一般会自动补上）
  - **金额不符**：订单金额与支付金额不一致
  - **缺退款单**：订单已退款但无退款记录
- 出现差异会同时产生**严重级告警**

> 对账用于度量验收指标「订单、核销、通行、财务数据一致率 ≥ 99.9%」。与微信账单的直接比对需配置商户证书后启用。

### 4.3 报表导出
在各列表页右上角点「导出 CSV」，或「运营分析」页的导出下拉。支持：

| 报表 | 内容 |
| ---- | ---- |
| 订单明细 | 一行一位游客，含订单号、票种、金额、游客姓名、脱敏证件号、支付单号 |
| 核销记录 | 核销时间、渠道、闸机、游客 |
| 通行记录 | 入园/出园、结果、拒绝原因、闸机 |
| 退款单 | 申请/实退金额、手续费、状态、审核与完成时间 |
| 经营日报 | 每日预约/核销/进出园/实收/退款 |

- 导出文件为 CSV（UTF-8 BOM），**Excel / WPS 直接双击打开，中文不乱码**
- 金额单位为「元」，状态为中文，证件号已脱敏
- **导出动作会记入操作日志**（谁、何时、导了什么）

## 五、运维：闸机与告警

### 5.1 闸机设备
「闸机管理 → 闸机设备」查看每台闸机的编号、位置、方向、**在线状态**与最后心跳。

- **离线 90 秒**后服务端自动标记离线并产生告警
- 离线行整行标红，便于快速定位
- 「远程控制」下拉：单次开闸 / 常开 / 常闭 / 重启
  - **常开**用于应急疏导或消防联动，操作前请确认现场安全
  - **重启**会导致闸机短暂离线（约 30 秒）
- 「通信日志」查看该闸机最近的请求/响应报文，排查联调问题

**登记与编辑（需要「景区管理员」角色）**：「新增闸机」建新设备，行内「编辑」改名称 / 位置 / IP /
方向 / **所属景区** / 启用禁用 / 密钥，行内「删除」只允许删**还没跑过**的设备（有通行、日志、
告警记录的一律拒绝 —— 那些记录会失去归属）。几条要注意的：

- **闸机编号是设备身份**（走 `X-Gate-No` 头），全局唯一，而且**多景区也不能重名** ——
  用前缀区分：`A-北门` / `B-北门`
- **换景区**：景区被删或需要换绑时，用「编辑」里的「所属景区」。换绑会拒掉旧的通行规则
  （见下），要连同规则一起改或清空
- **密钥只在新增那一次显示**，请当场抄进设备配置；之后列表里不再下发（换了密钥设备侧要同步改，
  否则签名校验会全部失败）
- 「状态」只有启用 / 禁用；**在线 / 离线 / 故障由心跳自动维护**，不是手工设的

### 5.1.1 通行规则（闸机只放行哪些时段 / 票种）

在闸机的「编辑」抽屉里：**允许的时段**、**允许的票种**两个多选。都留空 = **不限**（默认）。

- 典型用法：**团体通道**只放行团体票种；**侧门**只在某个时段开（比如仅放行早场）
- 配了规则之后，游客的预约时段/票种不在其中，这台闸机会拒绝并提示「该闸机不放行此时段
  （...），请走其他通道」—— 现场按提示引导游客走对应通道即可
- **规则同时下发给闸机**：断网时离线核验也按同一套规则拦，白名单里不会出现不该走这条通道的人
- 跨景区的时段/票种**填不进去**（保存会报「时段不属于本景区」）—— 这是故意的，
  否则规则会静默把所有人都拦下、看起来像设备坏了

### 5.2 告警中心
「闸机管理 → 告警中心」默认展示**未处理**告警：

| 类型 | 含义 | 建议动作 |
| ---- | ---- | -------- |
| 闸机离线 | 90 秒无心跳 | 检查设备电源/网络；确认后处理 |
| 尾随 | 红外/光幕检测到一人刷票多人通过 | 现场巡查 |
| 强行通过 | 未核验强行通过 | 现场巡查 + 记录 |
| 重复核销 | 已核销票再次出示 | 核实是否二维码外传 |
| 离线记录冲突 | 离线补传时该票已被在线核销 | 抽查是否为重复使用 |
| 承载量 80%/90%/100% | 在园人数达分级阈值 | 启动客流管控预案 |
| 对账差异 | 三方数据不一致 | 财务核查 |

**严重级告警（红色）建议当班处理并填写备注**，处理记录会留存。

### 5.3 数据备份
「运维 → 数据备份」：

- 系统每日 03:00 自动备份（保留 30 天，过期自动清理）
- 可「立即备份」：建议在业务低峰期执行（备份有 IO 开销）
- 可下载备份文件留存到对象存储
- **恢复不提供界面操作** —— 覆盖生产库属高危操作，需按《部署与运维手册》由人工执行

## 六、管理层：看板与运营分析

### 6.1 实时看板
「数据看板 → 实时看板」（可投屏）：

- **当前在园人数**（大字号）+ 承载率进度条（≥80% 黄、≥90% 红）
- 今日预约 / 核销 / 核销率 / 入园 / 出园 / 拒绝通行
- 闸机在线率、待处理告警数（含严重告警数）
- 渠道分布、24 小时分时趋势
- 支持 10 秒自动刷新

> 口径：在园人数 = 累计入园 − 累计出园，仅「通过」与「应急放行」计入；实时值走缓存，每 5 分钟用通行记录校准。

### 6.2 运营分析
「运营分析」页支持近 7 天 / 近 30 天 / 自定义区间：

- **核心指标**：核销率、爽约率、退单率、实收金额
- **预约与经营趋势**：预约/核销人数与收入走势
- **客流分析**：分时 / 按日 / 按月切换
- **票种分析**：各票种销量、收入与占比
- **渠道分析**：各渠道订单量与金额

> ⚠️ **口径提示**：预约侧指标（预约/核销/爽约）按**预约日期**归集；资金侧指标（收入/退款）按**支付时间**归集。跨月对比时注意二者日期口径不同。

## 七、常见问题

**Q：小程序上看不到票 / 无法下单？**
按顺序检查：① 票种是否「上架」② 该日期是否已生成库存 ③ 时段是否「启用」④ 是否达到限购上限（同一证件每日限购默认 1 张）。

**Q：游客说付款了但订单还是「待支付」？**
支付回调可能延迟或丢失。系统每 5 分钟自动查单补偿；超过 5 分钟仍未变，让游客在订单页点「刷新」或重新发起支付（不会重复扣款）。

**Q：余票显示与实际不符？**
库存列表的「剩余」= 总库存 − 已售 − 已锁定。游客下单未付款的会占用「锁定」15 分钟，超时自动释放。

**Q：如何临时增加某天某时段的票？**
「票务管理 → 库存管理」找到该行 → 「调整库存」输入正数（如 50）→ 填写原因。系统会拒绝把总库存调到低于已售+锁定。

**Q：游客要改日期怎么办？**
当前版本支持**退款后重新预约**（后台审核退款 → 游客重新下单）。改签功能为 P2 需求，规划中。

**Q：导出报表是乱码？**
导出的是 UTF-8 BOM 的 CSV，用 Excel 直接打开即可。若用其他工具请选择 UTF-8 编码。

**Q：忘记密码？**
联系超级管理员在「系统管理 → 管理员」中重置。

**Q：为什么有些按钮我看不到？**
系统按角色控制菜单与按钮。例如「退款审核」只有景区管理员和财务可见。如确需权限请联系超管在「系统管理 → 角色权限」调整。

**Q：我在「参数配置」改了平台名称，小程序上没变？**
小程序在**启动时**拉一次平台信息，所以彻底杀掉小程序再重进即可（不用重新构建、也不用发版）。
另外顶栏之外还有几处品牌文案（`pages.json` 里的页面标题、`manifest.json` 的应用名）属于**构建期**配置，
换品牌时仍需改这些文件并重新构建。

**Q：后台改了退改规则，退款手续费怎么没变？**
先看该**票种**有没有自己的退改规则 —— 票种自身的规则**按字段覆盖**全局配置
（在「票务管理 → 票种管理」里看）。只有票种没设的字段才用「参数配置」里的 `refund` 兜底。
另外手续费是按**日历日**算的：距入园日还有 `beforeDay` 天及以上免手续费，落在窗口内按 `feeRate` 收。
想确认配置真的生效，可让运维跑 `npm run smoke:config`。
