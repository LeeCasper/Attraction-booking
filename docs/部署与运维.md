# 部署与运维手册

景区预约管理及门禁联动系统 —— 部署、配置、备份恢复与故障排查。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
| ---- | ---- | ---- |
| Node.js | ≥ 20.19 | 服务端与前端构建（实测 22.x） |
| pnpm | ≥ 8.7 | 仅 admin-web 需要（monorepo workspace） |
| MySQL | 8.0 | utf8mb4，时区 +08:00 |
| 服务进程 | Node 20+ | **时区须与业务时区一致**（默认 `Asia/Shanghai`）。<br>业务日期由 `BUSINESS_TZ` 显式决定，但 `@Cron` 的触发时刻仍按进程时区 —— 两者不一致会让日结在错误的时刻跑 |
| Redis | 7.x | 库存预减、在园人数、权限缓存、限流计数 |
| Nginx | 任意近期版本 | TLS 终止、静态资源、反向代理 |
| Docker | 可选但推荐 | 开发环境与 MySQL/Redis 编排 |

## 2. 部署拓扑

```
                    ┌──────────────────────────┐
   小程序 / 后台 ────▶│  Nginx (443, TLS)        │
   闸机           ────▶│  · 静态资源 admin-web/dist│
                    │  · /api  → server:3000   │
                    │  · /pay  → server:3000   │
                    └───────────┬──────────────┘
                                ▼
                    ┌──────────────────────────┐
                    │  server (NestJS) ×2      │
                    └────┬──────────────┬──────┘
                         ▼              ▼
                  ┌──────────┐   ┌──────────┐
                  │ MySQL 8  │   │ Redis 7  │
                  └──────────┘   └──────────┘
```

**要点**：

- 服务端是**无状态**的，可直接水平扩展（Nginx 轮询即可）；权限缓存与库存预减都在 Redis，多实例安全
- 定时任务（超时取消、查单补偿、心跳巡检、承载量预警、对账、备份）**多实例部署时会重复执行**，需二选一：
  - 生产建议把定时任务单独拆一个实例（设置 `ENABLE_JOBS=false` 给其余实例，或单独启动一个只跑 job 的进程）
  - 或接受重复执行 —— 任务本身都是幂等的（对账 ON DUPLICATE KEY、备份有 running 锁），仅浪费少量资源
- 微信支付回调（`/pay/wx/*`）**必须公网可达**，见 §5

## 3. 环境变量清单

复制 `server/.env.example` 为 `server/.env` 后逐项填写。**改完必须重启服务**（nodemon 只监听 src）。

### 3.1 必需项

| 变量 | 说明 |
| ---- | ---- |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_DATABASE` | MySQL 连接 |
| `REDIS_HOST` / `REDIS_PORT` | Redis 连接 |
| `JWT_SECRET` | 管理端 JWT 密钥，**必须改为随机 32+ 字符** |
| `JWT_MINI_SECRET` | 小程序端 JWT 密钥（默认由 JWT_SECRET 派生，生产建议独立） |
| `CRED_SECRET` / `CRED_SECRET_VERSION` | 动态凭证签名密钥，**必须改** |
| `AES_KEY` | 身份证/手机号加密密钥（**改了会导致已加密的历史数据无法解密，务必固定并纳入密钥管理**） |
| `IDCARD_HASH_SALT` | 证件哈希盐值（同上，改动后历史限购/黑名单匹配会失效） |

### 3.2 密钥轮换

动态凭证密钥支持滚动轮换，避免轮换期间闸机验签失败：

```bash
# 从 v1 换到 v2
CRED_SECRET_VERSION=2
CRED_SECRET=<新密钥>
CRED_SECRET_PREV_VERSION=1
CRED_SECRET_PREV=<旧密钥>
```

新签发的凭证用 v2，旧凭证在有效期内仍可用 v1 验签。观察一个凭证周期（1 分钟）后可移除 PREV 配置。

### 3.3 小程序与微信支付

见 §5 的配置清单。

### 3.4 其他

| 变量 | 默认 | 说明 |
| ---- | ---- | ---- |
| `WX_MOCK` | 无 AppID 时 true | 小程序登录模拟开关，**上线必须 false** |
| `WXPAY_MOCK` | true | 微信支付模拟开关，**上线必须 false** |
| `GATE_SIGN_TOLERANCE_SECONDS` | 60 | 闸机签名时间容差（防重放窗口） |
| `BACKUP_DIR` | `./backups` | 备份目录 |
| `BACKUP_DUMP_BIN` | 自动探测 | mysqldump 路径；容器化部署时可指向包装脚本 |

## 4. 部署步骤

### 4.1 首次部署

```bash
# 1) 建库建表（容器方式会自动执行 init.sql；自建 MySQL 则手动导入）
mysql -uroot -p < deploy/sql/init.sql

# 2) 服务端
cd server
cp .env.example .env && vi .env          # 按 §3 填写
npm ci
npm run build
npm run seed                             # 幂等：角色/权限/超管/示例闸机/参数配置
node dist/main.js                        # 或用 pm2/systemd 托管

# 3) 后台前端
cd ../admin-web
pnpm install
# .env.prod 中 VITE_SERVICE_BASE_URL=/api（同源，由 Nginx 反代）
pnpm build                               # 产物在 dist/，交给 Nginx
```

### 4.2 Nginx 参考配置

```nginx
server {
  listen 443 ssl http2;
  server_name your-domain.com;
  ssl_certificate     /etc/nginx/certs/fullchain.pem;
  ssl_certificate_key /etc/nginx/certs/privkey.pem;

  # 后台管理前端
  root /var/www/attraction-booking/dist;
  location / { try_files $uri $uri/ /index.html; }

  # 服务端 API
  location /api/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 10m;          # 团体订单批量导入预留
    proxy_read_timeout 60s;
  }

  # 微信支付回调（必须公网可达、无鉴权、无重定向）
  location /pay/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
  }

  # 闸机接口建议按设备来源限流，避免重试风暴
  location /api/gate/ {
    limit_req zone=gate burst=20 nodelay;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
  }
}
# http 强制跳转 https
server { listen 80; server_name your-domain.com; return 301 https://$host$request_uri; }
```

### 4.3 生产启动（systemd 示例）

```ini
# /etc/systemd/system/attraction-booking.service
[Unit]
Description=Attraction Booking Server
After=network.target mysql.service redis.service

[Service]
WorkingDirectory=/opt/attraction-booking/server
EnvironmentFile=/opt/attraction-booking/server/.env
ExecStart=/usr/bin/node dist/main.js
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

## 5. 微信支付上线配置清单

> 服务端启动时会做**配置自检**：`WXPAY_MOCK=false` 时若缺项，会在启动日志里以 `ERROR` 列出全部缺失项。配置完成后应看到 `微信支付配置自检通过（真实模式）`。

### 5.1 需要准备的凭据

| 配置项 | 从哪获取 |
| ------ | -------- |
| `WXPAY_MCHID` | 微信支付商户平台首页（商户号） |
| `WXPAY_APPID` | 小程序 AppID（**必须与商户号绑定**） |
| `WXPAY_SERIAL_NO` | 商户平台 → 账户中心 → API安全 → API证书（40 位十六进制） |
| `WXPAY_PRIVATE_KEY_PATH` | 下载 API 证书得到的 `apiclient_key.pem` 的**绝对路径** |
| `WXPAY_API_V3_KEY` | 同页面「APIv3 密钥」，**由你自己设置的 32 位字符串**，用于回调报文解密 |
| `WX_APPID` / `WX_APP_SECRET` | 小程序后台 → 开发管理 → 开发设置（AppSecret） |
| `WXPAY_NOTIFY_URL` | `https://你的域名/pay/wx/notify` |
| `WXPAY_REFUND_NOTIFY_URL` | `https://你的域名/pay/wx/refund/notify` |

**三个易混概念**：

- **商户 API 证书**（`apiclient_key.pem` + 序列号）→ 你的，用于**请求签名**
- **APIv3 密钥**（32 位字符串）→ 你自己设的，用于**回调报文 AES 解密**
- **平台证书** → 微信的，代码自动下载缓存，**不需要你配置**

### 5.2 商户平台需要完成的事

1. 商户号与小程序 AppID **绑定**（产品中心 → APPID账号管理）
2. 开通 **JSAPI 支付**
3. 开通 **退款** 权限（部分商户默认无）
4. 结算银行卡已绑定、实名认证通过
5. 小程序服务器域名白名单加入 API 域名（小程序后台 → 开发管理 → 服务器域名）

### 5.3 切换与验收

```bash
WX_MOCK=false          # 小程序登录走真实 code2session
WXPAY_MOCK=false       # 支付走真实交易
# 重启服务，确认自检输出
```

验收顺序（建议用 1 分钱小额真实支付）：

1. 下单拿到 `payParams` → 小程序 `wx.requestPayment` 拉起支付
2. 支付完成，日志出现「支付成功」；订单状态变 20；`payment` 表落 `transaction_id`
3. **回调丢失演练**：临时改错 `WXPAY_NOTIFY_URL` 完成支付，等 5 分钟看「查单补偿」是否自动补记
4. 申请退款 → 后台审核 → 微信退款到账 → 订单状态 60、库存回流
5. 次日 08:00 对账任务执行后，查看「对账」页面应无差异

## 6. 备份与恢复

### 6.1 自动备份

- 每日 **03:00** 自动执行（`mysqldump --single-transaction` + gzip），文件落在 `BACKUP_DIR`
- 保留 **30 天**，过期文件自动清理
- 记录写入 `data_backup` 表，可在后台「运维 → 数据备份」查看与下载

### 6.2 手动备份

后台「数据备份」页点「立即备份」，或：

```bash
curl -X POST http://localhost:3000/api/admin/backups/run -H "Authorization: Bearer <token>"
```

### 6.3 恢复演练（**覆盖生产库，需人工执行并先确认**）

```bash
# 1) 停止应用，避免恢复期间写入
systemctl stop attraction-booking

# 2) 解压恢复（务必先备份当前库！）
gunzip -c /path/to/backups/attraction_booking_20261008_030000.sql.gz > /tmp/restore.sql
mysql -uroot -p attraction_booking < /tmp/restore.sql

# 3) 重启并验证
systemctl start attraction-booking
npm run smoke && npm run smoke:order && npm run smoke:gate
```

**建议每季度做一次恢复演练**，在测试库上验证备份可用性 —— 未验证过的备份等于没有备份。

### 6.4 备份策略建议

| 场景 | 建议 |
| ---- | ---- |
| 日常 | 保留 30 天本地备份（已内置） |
| 生产 | 每日备份上传对象存储（OSS/COS），异地留存 |
| 大促/节假日 | 活动前手动备份一次，便于快速回滚 |
| 密钥 | `AES_KEY` / `IDCARD_HASH_SALT` **必须单独妥善保存**，丢失则历史加密数据无法解密 |

## 7. 监控与告警

### 7.1 系统自带告警

后台「闸机管理 → 告警中心」会汇聚以下告警（都写 `alarm` 表）：

| 类型 | 触发条件 | 级别 |
| ---- | -------- | ---- |
| `gate_offline` | 闸机 90 秒无心跳 | 严重 |
| `tailgate` / `force_pass` | 闸机上报尾随/强闯 | 由闸机定 |
| `duplicate_verify` | 已核销票重复出示 | 警告 |
| `offline_conflict` | 离线记录同步冲突 | 警告 |
| `capacity_80/90/100` | 在园人数达承载量分级阈值 | 80% 警告，90%/100% 严重 |
| `reconcile_diff` | 对账发现差异 | 严重 |

### 7.2 建议外部监控

- 进程存活：`GET /docs` 或专用健康检查
- 接口成功率与 P99 延迟（核销接口应 < 500ms）
- Redis / MySQL 连接数与慢查询
- 磁盘余量（备份目录增长）

## 8. 常见故障排查

| 现象 | 排查方向 |
| ---- | -------- |
| 改了 `.env` 不生效 | **必须重启进程**（nodemon 只监听 src） |
| 启动报 `微信支付配置不完整` | 按日志列出的缺失项逐条补，见 §5 |
| 支付回调收不到 | 域名必须公网 HTTPS；Nginx `/pay/` 未被鉴权或重定向拦截；证书链完整 |
| 闸机验签失败 | 闸机 `secret_key` 与模拟器/真机配置是否一致；服务器与闸机时钟偏差是否超过 60 秒 |
| 闸机提示「请求重复」 | nonce 重放保护生效；检查闸机是否在重试同一请求而未更换 nonce |
| 库存与订单对不上 | 跑一次对账（`/admin/reconciliations/run?date=`）看差异明细；检查 Redis 是否被打满导致预减降级 |
| 在园人数明显异常 | 每日 5 分钟一次自动校准；也可手动调 `/admin/dashboard/realtime` 对比 `passage_record` |
| 重复核销被放行 | 不应发生 —— `verification.order_item_id` 有唯一索引；若发生请检查索引是否存在 |

## 9. 上线检查清单

- [ ] `JWT_SECRET` / `CRED_SECRET` / `AES_KEY` / `IDCARD_HASH_SALT` 已替换为随机值并妥善保存
- [ ] `WX_MOCK=false`、`WXPAY_MOCK=false`，启动自检通过
- [ ] 小程序 AppID 与商户号已绑定，白名单已配置
- [ ] Nginx HTTPS 证书有效，`/pay/` 公网可达
- [ ] 超管默认密码 `admin123` **已修改**
- [ ] 定时任务只在一个实例运行（或确认任务幂等可接受）
- [ ] 备份任务已跑通一次，且做过一次恢复演练
- [ ] 四套冒烟测试（`smoke` / `smoke:order` / `smoke:gate` / `smoke:m4`）在目标环境全绿
- [ ] 闸机真机到场后：核对 `secret_key`、时钟同步（NTP）、离线缓存策略
