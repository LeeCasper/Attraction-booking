# 部署流程 · res.artaides.com（Debian + Docker）

> **从零到上线的完整流程。从上往下做**，每步末尾都有一行验证；标「一次」的只需要做一遍。
> 设计决定（为什么 nginx 不进容器、为什么两个 MOCK 先留着）与踩过的坑见《部署与运维》§10。
>
> 只有两处要在**本机**做：第 6 步（构建后台管理端）、第 8 步（小程序切线上）。其余都在服务器上。

最终对外就三条路径，都在 `https://res.artaides.com` 下：

| 路径 | 是什么 | 由谁提供 |
| --- | --- | --- |
| `/api/**` | 小程序端 + 后台的接口（含 `/api/uploads/<file>` 读图） | 容器 `api`（nginx 反代） |
| `/pay/**` | 微信支付回调（**不在 `/api` 下**） | 容器 `api`（nginx 反代） |
| `/admin/**` | 后台管理端界面（静态 SPA） | 宿主机目录 `/srv/attraction/admin/` |

## 0. 前置条件（先确认这四样）

| # | 要确认的 | 怎么确认 |
| --- | --- | --- |
| 1 | 域名已解析到服务器 | 本机 `dig +short res.artaides.com` → 应输出服务器公网 IP |
| 2 | 服务器能 sudo、80/443 可用 | **这台机上已有 `ai.artaides.com` 的 nginx，不要去停它**，两个站共存 |
| 3 | 本机代码已推到 GitHub | 本机 `git push`（仓库是**私有**的，服务器取代码见第 2 步） |
| 4 | 域名已备案 | 小程序「request 合法域名」要求已备案；**没备案也能先跑**（开发版勾「不校验合法域名」） |

**可以后补的**：微信小程序 AppID/Secret、微信支付商户号与证书 —— 在拿到之前两个 MOCK 开关保持 `true`（内测模式，见第 3 步的安全提示）。

## 1. 服务器基础环境（一次）

```bash
# 时区：必须与 .env 的 BUSINESS_TZ、MySQL 的 --default-time-zone 一致（见 CLAUDE.md 约束 11）
sudo timedatectl set-timezone Asia/Shanghai && timedatectl | head -3
#  → 输出里 Time zone: Asia/Shanghai (CST, +0800)

# Docker（官方脚本；装完当前用户要重登一次才免 sudo，或者干脆都用 sudo）
curl -fsSL https://get.docker.com | sudo sh
sudo docker compose version          # → Docker Compose version v2.x

# nginx + certbot
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
nginx -v && certbot --version

# 如果开了 ufw 或云厂商安全组：放行 22 / 80 / 443，其余不用开
# （MySQL 3306 与 Redis 6379 都不发布到外网，compose 里只给了 127.0.0.1）
```

## 3. 环境变量（一次）

```bash
cd /srv/attraction/deploy
cp .env.production.example .env
chmod 600 .env          # 里面是库密码与三个密钥

# 四个随机值，分别粘到 .env 里对应的项（每个单独生成，别复用）
openssl rand -base64 48     # → DB_PASSWORD（顺带用它做 MySQL root 密码）
openssl rand -base64 48     # → JWT_SECRET
openssl rand -base64 48     # → CRED_SECRET（动态二维码签名）
openssl rand -hex 32        # → IDCARD_HASH_SALT（证件号哈希盐）
openssl rand -base64 32     # → AES_KEY（32 字节，证件号加密）

nano .env
```

**必改的项**：

| 变量 | 说明 |
| --- | --- |
| `DB_PASSWORD` | 同时是 MySQL 容器的 root 密码（compose 用同一份 `.env`） |
| `JWT_SECRET` / `CRED_SECRET` | 换成随机值 |
| `IDCARD_HASH_SALT` / `AES_KEY` | ⚠️ **上线后不要再改**：前者让同一张身份证算出不同哈希（限购会被绕过），后者会让**已加密的证件号解不出来** |

**按需改的项**：`BUSINESS_TZ`（默认 `Asia/Shanghai`）、`API_PORT`（默认 3000，只绑本机）、
`UPLOADS_DIR` / `CERTS_DIR`（默认 `/srv/attraction/uploads`、`/srv/attraction/certs`，改了要同步改第 7 步的 vhost）。

> ⚠️ **`WX_MOCK` / `WXPAY_MOCK` 目前是 `true`，这是内测配置**：mock 登录意味着**任何人**拿任意 code
> 就能换 token 调小程序端全部接口，支付/退款也是模拟的（不扣钱也不进账）。
> 所以：**域名先别往外发、别放真实用户数据**；拿到真实 AppID/Secret 与商户证书后按第 9 步改 `false`。

## 7. nginx + HTTPS（一次）

```bash
# 装 vhost
sudo cp /srv/attraction/deploy/nginx/res.artaides.com.conf /etc/nginx/sites-available/
sudo ln -s /etc/nginx/sites-available/res.artaides.com.conf /etc/nginx/sites-enabled/
sudo nginx -t          # → syntax is ok / test is successful

# ⚠️ 证书要**给 res 单独签一张**：这台机上现成那张是 ai.artaides.com 的，
#    拿它服务 res 会让浏览器与微信报证书不匹配（微信直接拒请求）
sudo certbot --nginx -d res.artaides.com
sudo nginx -t && sudo systemctl reload nginx     # ⚠️ 是 reload，不是 restart（别把 ai 那个站也断了）
```

**外网验证三条**（在任意机器上跑）：

```bash
curl -s https://res.artaides.com/api/mini/areas/overview | head -c 120        # 接口通
curl -sI https://res.artaides.com/admin/ | head -3                            # 后台 200
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' \
  https://res.artaides.com/api/uploads/<刚才 rsync 过去的某个文件名>           # 图片能取
echo | openssl s_client -connect res.artaides.com:443 -servername res.artaides.com 2>/dev/null \
  | openssl x509 -noout -subject                                              # 证书 subject 应是 res.artaides.com
```

到这里：**接口 + 后台 + 图片**三样都通了。去 `https://res.artaides.com/admin/` 登录并**改掉超管密码**。


## 9. 接真实微信支付（等你拿到商户号）

现在 `WXPAY_MOCK=true`，支付是模拟的。要接真的：

1. 证书放到宿主机：`/srv/attraction/certs/apiclient_key.pem`（compose 已把它只读挂到容器 `/app/certs`）
2. 改 `deploy/.env`：`WXPAY_MCHID`、`WXPAY_APPID`、`WXPAY_SERIAL_NO`、`WXPAY_API_V3_KEY`、
   `WXPAY_MOCK=false`；**同时**把小程序登录的 `WX_APPID` / `WX_APP_SECRET` 填上、`WX_MOCK=false`
3. 商户平台：配 JSAPI 支付授权目录 + 回调地址
   `https://res.artaides.com/pay/wx/notify` 与 `.../pay/wx/refund/notify`
4. 生效并验收：
   ```bash
   cd /srv/attraction/deploy && sudo docker compose -f docker-compose.prod.yml up -d
   sudo docker compose -f docker-compose.prod.yml logs api | grep -i "模拟模式"
   #  → 不应再出现「微信支付处于【模拟模式】」与「小程序登录处于【模拟模式】」两条 WARN
   ```
5. 走一遍真流程：小程序下单 → 真支付 1 分钱 → 看凭证页出码、后台订单变「已支付」

详细清单见《部署与运维》§5。

## 10. 日常更新 / 回滚

**更新后端**（本机 push 之后，服务器上）：

```bash
cd /srv/attraction && git pull && cd deploy \
  && sudo docker compose -f docker-compose.prod.yml up -d --build \
  && sudo docker compose -f docker-compose.prod.yml logs --tail 30 api
```

只改了 `deploy/.env`（没改代码）：`sudo docker compose -f docker-compose.prod.yml up -d` 即可（compose 会重建 api 容器）。

**更新后台**：本机 `pnpm build` → `rsync -av --delete dist/ 服务器:/srv/attraction/admin/`（不用重启任何东西）。

**更新小程序**：本机 `npm run build:mp-weixin` → 开发者工具上传。

**回滚**：`cd /srv/attraction && git log --oneline -5` 找到上一个好版本 →
`git checkout <commit>` → 回 `deploy/` 重新 `up -d --build`；事后 `git checkout master` 回到主线。

> ⚠️ **改表结构不在这条链里**：`deploy/sql/init.sql` 只在**数据卷为空**时被 MySQL 执行一次。
> 上线后加字段/加索引要**手动 ALTER**（见 CLAUDE.md「表结构权威来源是 SQL」），
> 而且 `down -v` 会**删库**，永远别在生产上用它。

## 11. 排障速查

| 现象 | 先看什么 | 常见原因 |
| --- | --- | --- |
| **文字有、图全裂** | 在手机浏览器里直接打开那张图的 URL | ① 上传目录没搬过去（第 4 步）② nginx `alias` 路径与 `UPLOADS_DIR` 不一致 ③ 容器里的文件宿主 `www-data` 读不到（目录 755 / 文件 644） |
| 小程序连不上、一直转圈 | `curl https://res.artaides.com/api/mini/areas/overview` | 域名没备案/不在合法域名列表（开发版可勾「不校验合法域名」）、证书不匹配 |
| 502 Bad Gateway | `sudo docker compose ... ps` | api 容器没起来 → `logs api` 看报错（多半是 `.env` 少了必填项或连不上 mysql） |
| 支付回调收不到 | `curl -I https://res.artaides.com/pay/wx/notify` | 回调路径**不在 `/api` 下**，vhost 里 `/pay/` 那段要单独放行；商户平台填的地址要完全一致 |
| 后台能开但接口全 404 | 浏览器 Network 里看请求地址 | 后台构建时 `VITE_BASE_URL` 不是 `/admin/`（资源 404），或 `VITE_SERVICE_BASE_URL` 不是 `/api` |
| 凌晨「未到预约日期」/ 日结差一天 | 服务器 `timedatectl`、容器 `TZ`、`.env` 的 `BUSINESS_TZ` | 三者必须都是 Asia/Shanghai（CLAUDE.md 约束 11） |
| 容器反复重启 | `sudo docker compose ... logs api` | 缺必填 env（compose 会直接报 `DB_PASSWORD 必须给`）、磁盘满 |
