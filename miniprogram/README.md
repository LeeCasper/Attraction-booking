# 游客端小程序（uni-app）

景区预约管理及门禁联动系统的游客端，**uni-app + Vue3 + Vite + TypeScript**，只编译微信小程序（mp-weixin）。

一期是 **1:1 界面还原 + 本地交互**：数据用设计稿原文硬编码，尚未接后端接口。

## 现状

| 页面 | 设计稿 | 静态还原 | 视觉动效 | 本地交互状态 |
| --- | --- | --- | --- | --- |
| 景区预约首页 | `design/reference/home.html` | ✅ | ✅ 景点封面自动轮播（4.2s）+ 呼吸点、按下态 | ✅ 点轮播某一屏 / 推荐景点卡片 → 该景点的购票页 |
| 分时预约购票页（二级页） | `design/reference/booking.html` | ✅ 由生成器产出 | ✅ 日期条横向滚动 + 两端渐隐 | ✅ 选日期 / 选时段 / 勾游客 / 新增出行人 / 底部金额联动 |
| 订单支付页（二级页） | `design/reference/pay.html` | ✅ 由生成器产出 | ✅ 支付倒计时每秒走 | ✅ 协议勾选控制支付按钮 / 金额明细抽屉展开收起 |
| 动态防伪电子凭证页 | `design/reference/credential.html` | ✅ | ✅ 60s 倒计时、二维码刷新、水印时间戳 | ✅ 通行方式三选一 |
| 个人中心 | `design/reference/profile.html` | ✅ | ✅ 按下态 | ✅ 四态筛选 / 刷新离线凭证 → 轻提示 |
| 景点选择与预约（外壳第 2 格） | `design/reference/areas.html` | ✅ 由生成器产出 | ✅ 按下态 | ✅ 分类真筛 / 搜索过滤 / 选中景点 / 去预约 / 筛选弹层 |

> 设计稿里**没有**「展开/收起」控件（早先的说明有误）：个人中心真正可交互的只有那排四态筛选按钮，
> 以及「刷新离线凭证 → 顶部轻提示 2s」—— 后者设计稿自带一段原生 JS 实现。

**接口已全部接上**：4 个视图的数据都来自 `/api/mini/*`，**选景点 → 购票 → 下单 → 支付 → 凭证**整条链路打通；
另有 6 个二级页：**有设计稿走生成器的**是「景点选择与预约」（`areas.html`）、**订单支付**（`pay.html`）、
**景区地图与景点**（`map.html`，首页「便民服务 → 景区地图」进来）；「我的预约」「订单详情」「常用出行人」
是设计稿里没有的、版式自拟。仍是静态的部分（后端没有对应数据，不是漏做）逐项列在 [已知偏差](#已知偏差) 里。

**「立即预约」之后是支付页**（`pages/pay/`）：购票页只**建单**，库存从建单那刻锁住、支付截止时间同时起算，
然后压栈进支付页 —— 应付总额、倒计时、支付方式、协议勾选都在那一页（设计稿单独画的一页）。
「我的预约 → 详情 → 去支付」也落到同一个地方，两处不再各写一套支付逻辑。

**品牌名不在代码里**：顶栏的名称/英文名/副标题/**Logo**、凭证水印的「XX验真」、个人中心的页脚版本号，
全部来自 `GET /api/mini/platform/settings`（后台「系统管理 → 参数配置 → platform」维护，Logo 那一栏**可直接上传**；
留空或路径指不到图时用设计稿那个青绿渐变方块 —— 见 `PageHeader.vue` 的 `@error` 兜底；
**上传的是透明 PNG 时那个方块会自动去掉**（`.pg-header__logo--plain`：不留外框），
启动时由 `src/store/settings.ts` 拉一次并落盘缓存 —— 所以**改品牌名不用重新构建**，重启小程序即可。
购票页头卡标题跟随**当前景点**（与「多景区」口径一致）；个人中心那张「最近一单」卡的景点名取自**订单自己的** `scenicAreaId`（订单在哪个景点买的就是哪个）。

## 已实现的动态效果

设计稿虽然只有静态 HTML，但它在元素 `id` 上预留了交互钩子
（`countdown-text`、`dynamic-qr-svg`、`calendarScroll`、`dateScrollLeftFade` …）。
生成器按这些 id 把行为注入进去（见 `scripts/page-bindings.mjs`），
**版式仍由设计稿生成，动态逻辑写在手写的 `views/*/behavior.ts` 与组件里**。

| 效果 | 实现 | 备注 |
| --- | --- | --- |
| 凭证 60 秒倒计时 | `pages/credential/behavior.ts` | 归零自动刷新二维码。时长 60s、首屏 41s 取自设计稿；接接口后改用 `credential.expiresIn` |
| 二维码刷新 | `components/DynamicQr.vue` | `seed=0` 用设计稿原图案（保证首屏逐像素一致），刷新时按确定性 PRNG 重排数据点、三个定位角不变 |
| 防伪水印时间戳 | 同上 | 三行水印各带当前 `HH:mm:ss`，每秒更新 |
| 日期条两端渐隐 | `pages/booking/behavior.ts` | 监听 `scroll-view` 的 scroll，按滚动位置切 `is-on`/`is-off` |
| 呼吸点 / 刷新旋转 | `styles/utilities.scss` 的 `@keyframes pg-pulse` / `pg-spin` | 由 `animate-pulse` / `animate-spin` 类驱动，两个产物里都已确认生成 |
| 按下态 | 生成器把设计稿的 `active:*` 类挂到 `hover-class` | 见下「按下态必须用 hover-class」 |

### 按下态必须用 hover-class，不能用 `:active`

设计稿有 9 处 `active:*`（`active:scale-[0.98]` / `active:rotate-180` / `active:opacity-90` …）。
生成器最初把它转成 CSS `:active` 伪类 —— 在 H5 里有效，但**微信小程序的 `<view>` 不触发 `:active`**，
真机上一个反馈都没有。现在做法是：

1. `gen-utilities.mjs` 把 `active:*` 生成为**普通类**（`.active-scale-0_98 { transform: scale(.98) }`），不写伪类
2. `gen-pages.mjs` 把这些类从元素的 `class` 里**摘出来**，改挂到 `hover-class` 属性上

`hover-class` 在 H5 与小程序两端都生效，所以这是唯一可靠的写法。

### 交互状态怎么落地：手写组件 + 按 id/class 注入

设计稿只画了**一种**选中组合（10-09 那天选中、08:30-10:30 那个时段选中），
其余状态得自己推。做法是把**只有交互区**抽成手写组件，页面版式仍由设计稿生成：

| 组件 | 挂在设计稿的 | 承载的状态 |
| --- | --- | --- |
| `DateCards.vue` | `#calendarScroll`（`inner`，容器留在页面） | 8 天单选；`约满` 不可选；胶囊三态 |
| `SlotGrid.vue` | `#slotGrid`（`replace`） | 4 时段单选；选中带 `check` 角标 |
| `VisitorPicker.vue` | 游客卡容器（按 class 定位） | 勾选游客、`已选 N 人 / 限购 M 人` |
| `BookingBar.vue` | `.fixed.bottom-16`（按 class 定位） | `待付 ¥{单价×人数} (N人)`；0 人时置灰 |
| `PassPicker.vue` | 通行方式 grid（按 class 定位） | 三选一 |
| `PassFilter.vue` | 四态筛选 grid（按 class 定位） | 四态单选 |
| `AppToast.vue` | `#toastNotification`（`replace`） | 通用轻提示，显现 2s |

绑定规则写在 `scripts/page-bindings.mjs`，由 `gen-pages.mjs` 执行：

- 键可以是 `#id`，也可以是 **class 列表**（`a b c` 子集匹配，`= a b c` 全等匹配）——
  因为**设计稿不是每个交互区都留了 id**：凭证页的通行方式、购票页的游客登记与底部待付条，一个 id 都没有。
- **匹配数必须恰好 1，否则 `npm run gen` 报错并跳过该页**。这是防错的安全阀：
  选择器写宽了会静默改错元素，写窄了会静默不生效，两种都极难排查，所以直接让构建炸。
- `replace` 会把 **id 一起换掉**（元素整个被组件替换），`inner` 只换子节点、保留元素自身。

**两个组件布局上的坑**（踩过）：

1. 自定义组件会**多一层节点**。若把 grid/flex 容器留在页面上、`v-for` 项放在组件里，
   子项就不再是容器的直接子元素，**栅格会塌**。所以 `replace` 用于容器时，
   组件根节点必须自己带容器的 class（各组件里的 `GRID` / `CARD` / `BAR` 常量就是干这个的）。
2. uni-app 的 `<scroll-view>` 会把子元素包进内部容器，布局类必须挪进内层 ——
   日期条改用 `inner` 注入组件后，那层 flex 滚动类就归 `DateCards` 的根节点了。

### ⚠️ 设计稿没给样本、由推断补上的状态

这几处**设计稿里没有对应样本**，是本实现按设计系统推断的。做验收时请按此核对，不要当成还原偏差：

| 处 | 设计稿只有 | 本实现的推断 |
| --- | --- | --- |
| 游客未勾选态的单选圈 | 「已勾选」一个样本（`border-2 border-primary` + `bg-primary/10` + 内层实心点） | 外圈改中性描边 `border-silk-border`、去掉 `bg-primary/10`、不渲染内层实心点 |
| 「选中 + 紧张」的日期卡 | 选中卡恒为「充足」，胶囊是白透底 `bg-white/20` | 选中卡的状态胶囊**统一用白透底**、只换文案；不叠加琥珀色（白透底在青绿渐变上可读，琥珀叠上去会脏） |
| 出行游客登记的**空态** | 设计稿画了 1 位出行人，没有「一位都没有」的样子 | 卡片内改成「圆圈图标 + 暂未添加出行人 + 点下方『新增出行人』登记」。**空卡片（`p-space-md` + 白底）会只剩一个空白圆角块，看着像渲染坏了**，所以必须有话可读；加载中另走 `正在加载出行人…`，不在没拿到数据时替用户下结论 |

另有一处**看着像 bug、其实设计稿原样如此**：个人中心那张卡底部那行小字**会被按钮挤到截断**
（`truncate`），两个按钮与它挤在一行 —— 设计稿参考图（`design/reference/shots/ref-profile.png`）
里一模一样，不是转换失真。所以那行小字一律写短句（十来个字），不写成一句话。

### 单页架构：为什么整站只有一个页面

**微信小程序里换「页面」，一定重建视图层，切换时一定会闪。**
`reLaunch`、`switchTab`、自定义 tabBar 都躲不开 —— 这是平台固有问题（社区从 2019 年反馈至今），
配置层面无法根除。所以本项目放弃多页面，改成：

```
src/pages/main/index.vue          唯一页面（手写外壳）
  ├─ PageHeader                    只渲染一次
  ├─ .pg-shell__body               flex:1
  │    └─ 每个视图一个 scroll-view（v-if 懒挂载 + v-show 保留）
  │         src/views/{home,area,credential,profile}/index.vue       ← 生成器产出（外壳的 4 格）
  └─ TabBar                        只渲染一次，纯受控（只 emit，不导航）
```

切页 = 改一个 ref、CSS 显隐 —— **没有页面转场，就不可能闪**；顶栏底栏也不再随切换重建。
`pages.json` 只剩 `pages/main/index` 一个页面，没有任何 tabBar 配置。

**底栏那 4 格与页面的对应关系**（底栏第 2 格是「景点选择」而**不是**购票页）：

| 底栏 | 内容 | 形态 |
| --- | --- | --- |
| 首页 | 景区预约首页 | 外壳视图 |
| **预约购票** | **景点选择与预约** | 外壳视图（设计稿自带固定标题栏，这一格由外壳让出顶栏位） |
| 电子凭证 | 动态防伪电子凭证页 | 外壳视图 |
| 个人中心 | 个人中心 | 外壳视图 |

**购票页（游览日期 / 入园时段 / 票种）不在这 4 格里**，它是「选完景点之后」才进入的
二级页 `src/pages/booking/index.vue`。这是产品口径：本平台管多个景点，用户点「预约购票」
的意图首先是「去哪个景点」，而不是「买上一个景点的票」。落成二级页还有个设计上的好处 ——
设计稿给购票页画的底部待付条是按「底栏之下」定位的，二级页没有底栏，待付条正好贴屏幕下沿。

> 反向的取舍：景点选择页的设计稿画了**返回键**。作为二级页它是对的，但它是根 tab、没有
> 「返回」可言，所以实现里把那个键去掉了（首页/凭证/个人中心三格的顶栏由外壳统一渲染，
> 这一格因为自带标题栏而由外壳让出位置）。

**每个视图各自的 scroll-view 是必需的**：只有一个页面时，若让文档滚动，
四个 tab 会共用同一个滚动位置（切过去会停在半路）。各自一个容器，滚动位置就互不干扰。

**懒挂载 + v-show，而不是一上来全挂载**：全挂载会让首屏同时渲染 4 个视图；
全用 `v-if` 则每次切换都重建组件、视图内的状态（购票页选好的日期、凭证倒计时）会丢。
折中是「首次访问才挂载，之后只做显隐」—— 顺带解决了一个隐蔽问题：
**视图首次挂载时一定可见**，所以购票页那段「量 date strip 宽度」的代码拿得到真实值，
`pages/booking/behavior.ts` 一行都不用为单页架构改。

**「从二级页返回」对视图是静默的 —— 视图重取数据必须看 `shellShowTick`：**
外壳只给视图传一个 `active`，而二级页（订单详情 / 支付页 / 购票页 / 出行人管理）压上来时
`active` 一直是 `true`，返回时也不会变 —— 视图里那句「首次可见才拉数据」的守卫于是不会重取。
症状是用户报的那一个：个人中心点「查看详情」→ 在详情里取消订单 → 返回，
「待支付」那一格还挂着**已经取消掉**的那一单；凭证页同理（从「申请退改」提交退款后返回，
二维码照样出得来）。修法是**外壳记一笔、视图各自判断**：
`pages/main/index.vue` 的 `onShow` 调 `store/shell.ts` 的 `markShellShown()`
（**视图拿不到 `onShow`** —— 它不是页面，只有外壳是），个人中心 / 凭证页各自 `ensureFresh()`：
没拉过、或「期间离开过外壳」（`shellShowTick` 变了）就重取，只在本格里切来切去则不动
（保留「首次可见才拉数据」的初衷）。二级页不受影响 —— 它们是真实页面，`onShow(load)` 就够。

**布局责任重新划分**（`gen-pages.mjs` 的 `VIEW_DROP`）：

| 设计稿 `<main>` 上的类 | 单页架构下 |
| --- | --- |
| `pt-16`（给固定顶栏让位） | **保留在视图上**。顶栏另补一个状态栏高度的占位块，见「已知偏差」 |
| `min-h-screen` | **去掉** —— 视图不再是整屏，高度由外壳的滚动容器给 |
| `pb-24` / `pb-28`（给底部 tab 让位） | **去掉** —— 改由 `TabBar.vue` 自己用一个等高占位块承担 |

**代价（务必知道）**：全站现在是**一个页面**。以后加详情页、下单页这类**真正的子页面**时，
把它们作为独立页面 `navigateTo` 上去即可（子页面本来也没有切换闪烁问题）；
但如果哪天需要「分享链接直接打开某个 tab」，得走 `pages/main/index` 的查询参数（目前没做）。

### 与后端的对接（数据来自哪里）

**请求层与登录态**（本轮新增）：

```
src/api/config.ts   baseUrl。⚠️ 小程序端必须用**开发机局域网 IP**（真机上 localhost 是手机自己）；
                    H5 预览走 localhost，后端已开 CORS，不用配 proxy
src/api/request.ts  uni.request 封装：注入 Bearer、拆 {code,msg,data}、code≠0 抛错、
                    **code=40100 时清 token 静默重登一次**
src/api/index.ts    按域分组的类型化接口（areas / tickets / stocks / orders / credential / visitors）
src/store/user.ts   token 与 profile 的存取 + ensureLogin()（并发只登一次）
src/store/order.ts  「当前订单」：下单支付成功后记住，凭证页据此取凭证
src/store/shell.ts  当前 tab —— 视图里也要能切页（下单成功 → 跳凭证页）
src/utils/format.ts 分→元、日期/星期、HH:mm:ss→HH:mm。**金额一律是分**，别在页面里自己 /100
```

| 订单详情页 | `src/pages/orders/detail.vue` —— **设计稿里没有这一页**。U-021 的六项 + 按状态给操作（取消 / 去支付 / 申请退款） |
| 选择景点页 | `src/pages/area/index.vue` —— **由设计稿生成**（`design/reference/areas.html`「景点选择与预约」，`gen-pages` 的 `standalone` 模式）。分类 tab **真筛**（后端 `scenic_area.category`）、搜索框本地过滤、卡片显示真实的分类/起价/今日余票。三个入口：底栏**「预约购票」**（压栈打开，见 `pages/main/index.vue` 的 `onTabChange`）、首页快捷卡**「在线预约」**、底栏之外从购票页返回 |

**首页的交互**（设计稿首页除底部 tab 外**没有任何 id**，所以点击行为全部按 class 或补的 id 定位）：

- **banner 是自动轮播**（`#homeBanner` → `components/BannerCarousel.vue`）：每一屏是一个景点，
  图取后台配的轮播图（一张都没配时按景点封面兜底），屏上的景点名/在园率/指示点都是**那一屏自己的数据**。
  点某一屏 → 选中该景点并进它的购票页。
  右上角那颗天气胶囊读 `store/settings` 的 `weather`（后端 `platform/settings` 里算出来的实况）：
  **拉不到 / 运营没配数据源 → 整块不渲染**（宁可少一块，也不显示一份不知道哪来的天气）；
  图标按后端给的**归一化类别**选（`rain → rainy`、`snow → ac_unit`…），
  认不出的类别只显示文字不画图标 —— 把沙尘暴画成太阳比少一个图标糟得多
- **「推荐景点」**（以前是「门票选购」）：三张景点卡（分类 / 今日真实余票 / 起价），点一张同样进购票页。
  「推荐」就是后端默认顺序（`status=1` 按 id 升序），后端没有推荐位/热度字段，不假装有排序规则
- 两张快捷卡：门票预约 → **景点选择**那一格（没有指向任何景点，所以先去选）；快速通关 → 凭证 tab（PRD 的 U-002）
- 公告条右侧的「须知」→ 如实提示「入园须知待接入」（后端没有独立的须知接口）

**「我的预约」的新交互**（三个此前**完全没有 `@tap` 的死入口**）：

- 个人中心「全部预约单」→ 订单列表（**不带筛选**：它叫「全部」，而列表页自己有四个筛选）
- 订单列表卡片的「**查看凭证**」（待入园/部分核销才有）→ 把这一单设成「当前订单」，
  退回外壳并切到凭证 tab。⚠️ 列表是压栈进来的**二级页**，光 `switchTab` 切不到凭证视图
  （外壳在它下面），要先按页面栈深度退到底（与支付页的 `backToShell()` 同口径）
- 个人中心那四个状态格 → **就地切换下面那张「最近一单」卡**（见下），不再跳走
- 凭证页「申请退改」→ 该单的订单详情（**后端没有改签**，所以只接退款；退款要填原因、还要能看审核状态）

订单操作按状态给，口径照服务端：**待支付**能取消与重新支付；**已支付**能申请退款（填原因，走后台审核）；
**部分核销**明确不给退款入口。

**多景区：切景点会动哪些数据**

`store/shell.ts` 的 `currentAreaId`（落盘）是唯一的「当前景点」。切它会让：

- **购票页**（票种列表、日期条、余票）重取 —— 它的 `loaded` 守卫记的是「按哪个景点加载的」，
  并在 `watch(currentAreaId)` 里作废 + 重取；`stockByDate` 余票缓存同时整体作废
- 首页**只重取公告**。首页本身已经与景点无关（轮播展示全部景点、推荐景点也是全部里的前三个），
  唯一按景点给的数据就是那条公告 —— 所以它在文案里带上景点名（`【嵖岈山】…`），
  换了景点只重取这一条，不再整页重取

另外要说明的是：**景点选择页点整卡只是「选中」，不再弹「已切换到 X」** ——
卡片自带 `ring-2` 选中高亮，那条提示没有信息量（首页也不再跟着它变了，见上）。
「去预约」是另一条路：`navigateTo` 压一张购票页上去，从购票页返回时回到的正是这一页。

> 首页以前是「当前景点的首页」：banner 是它的封面、下面三张票卡是它的票。于是用户在
> 「景点选择」页点一下别的景点，回到首页发现**整页都变了** —— 而用户只是想选中某个景点。
> 现在首页是**平台级**的，`currentAreaId` 只在「购票页买哪个景点的票」这一件事上有意义。

**不动**的：常用出行人（人级、跨景点通用）、**凭证页**（跨景点 —— 仍显示最近一张可入园订单，
但按订单自己的 `scenicAreaId` 标注景点名）、订单列表与个人中心（跨景点看全部更自然）。

> 副作用：**新建的景点没有票种/时段/库存**，切过去购票页会显示「该景点暂无可售票种」。
> 后台目前不会自动生成，要手动建。

**仍是静态的（后端没有对应接口，不是漏做）**：
首页的**开园状态**（天气已接真数据，见下）、便民四宫格（**「景区地图」那一格已接上**，另三格仍没有落点）；
**景区地图页整页内容**（4 个点位的名称/指标/客流百分比 —— 后端没有点位模型，
既没有「栈道/峡谷/索道/夜游」这些点位，也没有点位级的客流与排队时长；页面里唯一有行为的是
整页**没有任何交互**（顶部分类筛选按用户要求删掉了），两个按钮如实提示「待接入」）；
购票页的「限购 5 人」与入园须知文案；
凭证页的通行方式三选一、导出离线票、闸机联网状态；个人中心的用户资料（昵称/头像/手机号/实名）、
「年卡·优惠券」、门禁智联三行绑定状态、电子发票、履约信誉。
（「最近一单」卡本轮**已接真数据** —— 见下一条。）
**人脸**按技术方案 §7「三期前不采集」，那一行只能是 mock。
**改签（U-026）与发票（U-027）也没做** —— 后端根本没有：改签只有 `reschedule` 建表与
`ReservationStatus.RESCHEDULED` 枚举壳子，没有 entity/service/controller；开票连表都没有。

**本轮新增的已知偏差**：

| 项 | 原因 | 表现 |
| --- | --- | --- |
| **二维码是图案不是真码** | 把 token 编码成二维码矩阵需要引入编码器（本项目没有这个依赖）；闸机验的是 token 本体 | 图案由 token 推导（换码时图案会变），但**扫不出内容**。无订单时退回设计稿原图案 |
| **个人中心出行人卡第二行改了文案** | 设计稿写的是「已录入人脸 / 刷身份证过闸」这类**能力标签**，后端没有任何对应字段 | 改显示**脱敏证件号** —— 有真实信息量且不编造能力状态 |
| **接上真数据后部分文案与设计稿不同** | 设计稿的副标题、角标是占位文本，接口只给 `name`/`audience`/`price` 等字段 | 票种副标题取 `audience`（示例数据已按设计稿文案填，所以默认态一致；运营改了就会变） |
| **首页「门票选购」整节改成了「推荐景点」** | 那一节卖的是**当前景点**的票，于是首页的 banner 与门票都会跟着 `currentAreaId` 变 —— 用户在「景点选择」页点一下别的景点，回到首页发现整页都变了（他并没有要求首页跟着换）。首页该是平台级的 | 改成三张**景点**卡（分类 / 今日真实余票 / 起价，口径与景点选择页共用 `@/utils/area`），点一张进那个景点的购票页。「推荐」= 后端默认顺序（`status=1` 按 id 升序），后端没有推荐位/热度字段，所以不假装有排序规则 |
| **首页 banner 改成景点轮播图** | 设计稿按**单景区**画：一张写死的封面、写死「枫林谷森林公园」「在园率 38%」。本站管多个景点，一进小程序只看得见一个景点的图 | `components/BannerCarousel.vue`：`<swiper>` 自动轮播（4.2s），每屏的封面/景点名/在园率都是那一屏的数据，右下角多了指示点（**设计稿没有**，没有它用户不知道在轮播）。天气那一行读后端的真实数据（不再是设计稿那句写死的「晴 21°C」），每屏显示的是同一个平台级天气；拉不到就不显示 |
| **购票页多了「选择票种」一节** | 设计稿按单景区单票种画：票种在顶卡上写死成「成人全票 ¥120」。后台一个景点可以配多个票种，而从「景点选择」页进来的用户（现在的主路径）**没有任何换票种的入口**，默认永远是列表第一个 | `design/reference/booking.html` 里补了这一节，绑定注入 `components/TicketPicker.vue`：卡片选中态沿用同页「入园时段」那一节（`border-2 border-primary` + 浅青绿底），但**选中标记是行首的圆形单选圈**（与同页「出行游客登记」那个圈逐字相同），**不是时段格的右下角 check 角标** —— 角标 24×24 正好压在价格末尾，把 `/人` 盖掉一半（实测）。只列**按人计价**的票种（按张卖的进不了购票流程，后端只有「单价 × 人数」一种计价） |
| **「四季家庭年卡」这类按张卖的票种不再出现在购票页** | `saleUnit === 'ticket'`，而后端下单是硬编码的「单价 × 人数」，按人数会算成 ¥388 × N | 购票页的票种列表、首页推荐卡片的「起价」、景点选择页的「起价」都只认按人计价的票种；一个都没有时如实说「暂无可在线预约的票种」，点进购票页也是这句。`ticket_type.sale_unit` 就是为这个判定加的 |
| **控制台有 `Do not nest other components in the text component` 警告** | 设计稿把图标 `<span>` 放在文本 `<span>` 里，生成器按块级/行内规则转成了 `<text>` 里嵌 `<view>` | 仅告警，两个平台渲染均正常；属 Phase ① 就有的产物特征 |

## 开发

```bash
npm install

npm run build:mp-weixin    # 产物在 dist/build/mp-weixin
```

**微信开发者工具导入 `dist/dev/mp-weixin` 目录**（并让 `npm run dev:mp-weixin` 常驻），不是工程根目录；
**也请不要导入 `dist/build/mp-weixin`** —— 小程序源码根是 uni-app 的编译产物，不是 `src/`，
而 `build/` 是**生产构建**：`npm run build:mp-weixin` 每次都会先清空整个目录，
工具若正开着它，下一次构建就会撞上下面的「`module ... is not defined`」。
appid 已写在 `src/manifest.json` 的 `mp-weixin.appid`。

> **怎么判断工具当前开的是哪一棵**：导入项目时工具会往项目根写一份 `project.private.config.json`，
> 看它落在 `dist/dev/` 还是 `dist/build/` 下就知道了。

> 工程根目录**不放** `project.config.json`：uni-app 每次构建都会往产物目录里生成一份（含 appid），
> 根目录再放一份只会导致「改了不生效」的困惑。

### ⚠️ 代码明明改了，工具里一点变化都没有 —— 先关掉工程重新导入

**在怀疑代码之前先做这一步。** 症状是：改完、`npm run build:mp-weixin` 也跑完了、
开发者工具里点「编译」，界面还是老样子（这次实测：一个确实存在的改动，连着三轮复测都"没生效"，
最后**关闭工程 → 重新导入**就好了）。

原因和下面那节同源：`uni build` 会**先清空整个产物目录**再重写，而工具正开着该目录时
会读到半份产物；之后它的差量编译也不一定把所有改动重建回来。
`dist/dev` 那边有 watcher 就不会有这个问题（但工具默认打开的是 `dist/build`）。

### ⚠️ 改完代码后页面报 `module '...' is not defined`

先确认一件事：**工具的工程目录是哪一个。**

本机打开的其实是 **`dist/build/mp-weixin`**（`npm run build:mp-weixin` 的产物），
而 `npm run dev:mp-weixin` 的 watcher 写的是 **`dist/dev/mp-weixin`** —— **两个目录**。
挂在 build 上时，只跑 watcher 是一行改动都不会生效的，而现象看起来像「CSS 没压过」「代码没生效」。
**改完小程序源码记得补一次 `npm run build:mp-weixin`**；或者把工具的工程切到 `dist/dev/mp-weixin`，
那样 watcher 就够了。

判断当前工具开的是哪个目录（本机）：

```bash
grep -rho "/home/lee[^\"]*mp-weixin" ~/.config/wechat-devtools/ | sort | uniq -c | sort -rn | head
```

现象是在开发者工具里看到：

```
module 'pages/booking/behavior.js' is not defined, require args is './behavior.js'
Component is not found in path "wx://not-found"
```

**这不是代码问题**，产物本身完整、所有相对 `require` 都能解析（可用 `node` 逐文件核）。
是两个**工具侧**原因叠加：

1. **`uni build` 会先清空整个产物目录再重写。** 若工具正开着该目录，清空那一刻
   模拟器会扑空。工具日志里能看到铁证：一轮 `unlinkDir pages/...`（整目录被删），
   紧接着 `appservice simulator launch catch error Error: app.json: 在项目根目录未找到 app.json`，
   隔几秒才是 `add ...` 全量补回。
2. **新增的文件不会被热编译。** 保存改动会自动编译进工具，但**新加的文件除外**
   （uni-app 的既有行为）。本项目只在 Phase ① 新增过 `pages/*/behavior.js`，
   而报错也**恰好只出在这两个文件**上——同批的 `common/vendor.js`、`common/assets.js`
   因为早就在工程里，一直正常。这条差异把原因钉死了。

   > 这条与构建方式无关，**每次新增源文件都要留意**：交互组件那一批
   > （`DateCards`/`SlotGrid`/`VisitorPicker`/`BookingBar`/`PassPicker`/`PassFilter`/`AppToast`
   > 与 `pages/profile/behavior.ts`）就是 8 个新文件，构建后需要重新编译或重开项目一次。

**处理**（按顺序试，一般第一步就好）：

1. 开发者工具的 **清缓存 → 全部清除**，然后重新编译；
2. 还不行就 **关闭项目重新导入**（重开会把所有文件在启动时重新登记，绕开增量状态）；
3. 仍不行则换基础库版本或重装工具 —— 社区里 `require is not defined` 类问题有过这种解法。

### ⚠️ 删/改过页面路径后，白屏 + `el.split is not a function`

```
TypeError: MiniProgramError
el.split is not a function
    at ti (getMainPackageBundle.js)
```

同上一条的**镜像问题**：这次是**删掉或搬走**了页面/视图（例如把购票页从
`views/booking/` 搬到 `pages/booking/`、把 `pages/area/` 改成 `views/area/`），
而 `dev:mp-weixin` 的**差量编译不会清理已移除的产物** —— 旧目录还留在
`dist/dev/mp-weixin/` 里，工具的启动期索引于是自相矛盾。

排查顺序：

1. **先确认产物是干净的**（多半就是这一步）：
   ```bash
   # 源码里没有、产物里却还在的目录
   ls dist/dev/mp-weixin/pages dist/dev/mp-weixin/views
   node -e "console.log(require('./dist/dev/mp-weixin/app.json').pages)"
   ```
   对不上就**停掉监听器、`rm -rf dist/dev`、重新 `npm run dev:mp-weixin`**（差量编译救不了，必须全量）。
2. 再确认产物本身合法（这一步过了就说明**不是代码问题**）：
   ```bash
   # 每个页面的 usingComponents 相对路径是否都能解析到 .json/.wxml/.js
   ```
3. 然后才是工具侧：**清缓存 → 全部清除** → 重新编译；仍不行就**关闭项目重新导入**。

### ⚠️ 新增页面：先建 `.vue`，再往 `pages.json` 加路由

**顺序反了产物就永远缺这一页。** `pages.json` 里引用了尚不存在的页面时，
`npm run dev:mp-weixin` 的增量编译会打：

```
pages/orders/index not found
pages/orders/detail not found
```

然后**跳过这两页，并且后续的差量编译也不会重试**。产物目录里只剩一个 `.json`，
没有 `.js`/`.wxml` —— 表现和上面那个 `module ... is not defined` 一模一样。
实测踩过（本轮加订单列表/详情时）。

补救：**重启 watcher 做一次全量重建**（`npm run dev:mp-weixin` 重跑一遍）。
预防：先把 `.vue` 写出来，再改 `pages.json`。

**怎么避免再踩**：把工具切到 `dist/dev/mp-weixin`，让 `npm run dev:mp-weixin` 常驻。
dev 侧是**增量构建**——只重写变更文件、不做整目录清空，没有上述空窗期。
（注意第 2 条与构建方式无关，新增文件时仍需重新编译或重开项目。）

## 代码生成（重要）

设计稿是机器生成的 Tailwind 页面（615 个工具类、约 1000 个标签）。手抄既慢又必然出错，
所以**样式与页面模板都由脚本生成**——把转换规则写成确定的表，产物可复核、可重跑：

| 脚本 | 输入 → 输出 | 作用 |
| --- | --- | --- |

### 横向滚动条：内边距与吸附属于**滚动容器**，不属于滚动内容

设计稿里这一条是「一个 div 同时承担滚动容器与内容」：

```html
<div class="flex gap-2.5 overflow-x-auto py-2 snap-x px-4" id="calendarScroll"> …卡片… </div>
```

移植到 `<scroll-view>` 时**不能整串照搬到内容上**（`gen-pages.mjs` 的 `wrapInner`/`ownClass` 就是干这个的）。
踩过一次（购票页的游览日期条）：

| 类 | 放在滚动**内容**上会怎样 |
| --- | --- |
| `px-4` | 内边距跟着内容滚；而 `scroll-snap-type: x mandatory` 会把第一张 `snap-start` 卡吸附到**滚动端口**起点 —— 滚动端口是 padding box、不含内边距 ⇒ 那 16px 被滚掉，**第一张卡直接贴屏幕边**（实测 0pt，而票种卡/时段卡都在 16pt） |
| `overflow-x-auto` | 造出**第二层滚动容器**，真正滚动的是它 ⇒ 外面 `<scroll-view>` 的 `@scroll` 永不触发，两侧渐隐遮罩（靠它更新）永远不动 |
| `snap-x` | 属于滚动容器；而且用 `mandatory` 时哪怕内边距在容器上、吸附也会把卡片吸到贴边 —— 要配 `scroll-padding-left/right` |

所以：**内边距、`py-*`、吸附都放在 `<scroll-view>` 自己的类上**（购票页是 `pg-date-scroll`，
样式写在 `page-bindings.mjs` 的 `PAGE_BINDINGS.booking.style` 里），内容只留 `flex gap-*`。
吸附建议用 `proximity` 而非 `mandatory`：静止时不会被强行吸到贴边。

### 转换时的几个关键约定

- **`<div>` → `<view>`，`<span>` → `<text>`**：必须保留 HTML 的块级/行内区别。
  曾把两者都映射成 `<text>`，结果两个本该上下排列的元素挤成一行，整张卡片塌掉。
- **必须补 Tailwind preflight 的边框重置**（见 `App.vue` 的 `border-width: 0; border-style: solid`）。
  设计稿靠 preflight 把「没有宽度类」的边框压成 0；**我们漏了这条，于是凭空长出 3px 粗边框**：
  `border-dashed` 只设 `border-style`，没设宽度的三边会取 CSS 初始值 `medium` = 3px。
  表现是首页票卡里本应「只有上边一条虚线」的分隔线（`border-t border-dashed`），
  在实现里变成了四边 3px 的虚线方框。**这条一直没被发现，是因为它只在首页出现，
  而当时只逐像素比对了购票/凭证/个人中心三页。**
  （重置用标签选择器，特异性低于工具类，带宽度类的元素不受影响。）
- **类名做「消毒」**：WXSS 选择器对 `[ ] . ( ) # /` 支持不可靠，
  故 `text-[19px]` → `.text-19px`、`gap-2.5` → `.gap-2_5`、`bg-primary/10` → `.bg-primary_10`。
  完整映射表在 `design/classmap.json`。
- **输出顺序按 CSS 语义分层，不按字母序**：所有工具类都是单类选择器、特异性相同，靠后写的赢。
  按字母序会让 `border-t`（设 `border-style: solid`）排在 `border-dashed` 之后，把虚线覆盖成实线。
- **rpx 换算系数是 ×750/390（≈1.9231），不是 ×2**：设计画布 390pt（Stitch 报的 780 是 2 倍图），
  uni-app 约定 750rpx = 屏宽。按 ×2 会让元素在 390pt 机型上大约 4%。
  ≤1.5px 的细线与 box-shadow 的偏移量保持 px，避免低 DPR 取整后细线消失。
- **内联 `<svg>` 转成百分比定位的 `<view>`**：小程序没有 `<svg>` 标签。
  凭证页的二维码 SVG 是 `viewBox="0 0 100 100"` 下的 58 个 `<rect>`，按百分比还原后位置精确，无需 canvas。
- **背景图用绝对定位的 `<image>`，不用 `background-image`**：WXSS 禁止背景图用本地路径，
  外链（设计稿用的是 `lh3.googleusercontent.com`）在国内也不可达。
  配套的 `.pg-bgcontent` 负责把原始内容提到背景图之上（否则会被绝对定位的图片盖住）。

## 设计 token 与样式

`src/styles/tokens.scss` 是**唯一手写的事实来源**（67 个命名色、字号体系、间距、圆角、阴影）。
`gen-utilities.mjs` 会解析它取色值，所以改色只需改这一处。再跑 `npm run gen:utilities`。

变量与函数放在 `src/uni.scss`（uni-app 会自动注入每个 SFC 的 `<style>`，页面里可直接用
`$c-primary`、`px2rpx()`）。**`uni.scss` 及它 import 的文件里只能放变量与函数**——
它会被复制进每个组件的样式块，写选择器会让产物急剧膨胀。

全局规则（`box-sizing`、页面底色、`.pg-*` 结构类）在 `App.vue` 的 `<style>` 里。

> `box-sizing: border-box` 的全局声明不能省：`box-sizing` 不可继承，
> 漏掉它会让「`h-full` + `p-4`」算成「100% 内容高 + 32px 内边距」，撑破固定高度的容器。

### 字体：全站只有两套（改动前先读）

| 用在哪 | 族 | 变量 |
| --- | --- | --- |
| 标题（`headline-*`） | Noto Serif | `$font-serif` |
| **其余一切**（正文、金额、数字、角标、水印、英文标签…） | Plus Jakarta Sans | `$font-body` |

设计稿的第三套 Space Grotesk（`data-metric-*` / `display-kpi-screen` / `label-badge` /
`font-mono`）**已整个退役**，那四个类名在 `gen-utilities.mjs` 的 `FONT_TOKENS` 里都指向
`$font-body` —— 类名照旧（设计稿还在用），落地产物是正文族。

- **加新排版 token 时族只能从 `FONT_VAR` 里挑**：`gen-utilities.mjs` 有断言守着，写第三个族直接报错。
  不守的后果是产物里出现 `font-family: undefined`，静默忽略，最难查。
- ⚠️ **`.font-*` 与 `.text-*` 打架时谁赢**：`utilities.scss` 里 `.font-*` 排在 `.text-*` **之前**，
  而排版 token 类**自带 `font-family`**（Tailwind 的 `fontSize` 配置里并没有族，这是我们转换时
  另外加上的）。所以 `font-body-lg text-headline-lg` 这种组合里，**衬线会反过来压掉 `font-body-lg`**。
  要让一段文字走正文族、又要指定字号，用**不带族**的 `text-NNpx`（来自设计稿的 `text-[NNpx]`）。

## 依赖版本（改动前务必读）

uni-app 的 Vue3 线**没有纯稳定版**，全部是日期戳版本，且**各包必须完全一致**：

- `@dcloudio/*` 六个包统一钉 `3.0.0-alpha-5030120260930001`（`vue3` dist-tag）。
  注意 `latest` dist-tag 指向的是 **Vue2** 线（`2.0.2-*`），照它装会得到 Vue2 产物。
- `vite` 精确锁 `5.2.8` —— `vite-plugin-uni` 的 peerDependency 是**精确版本**，不是范围。
- `vue` 锁 `3.4.21` —— 与 `vite-plugin-uni` 内置的 `@vue/compiler-sfc` 对齐。
- `sass` 锁 `1.77.8` —— 更高版本会大量报 legacy JS API 弃用告警。
- 包管理器用 **npm**（不是 pnpm）：uni-app 的 vite 插件与 pnpm 严格符号链接存在已知摩擦。

不要把 `admin-web` 的依赖（`rolldown-vite@7`）与这里混用，两者 vite 主版本不同。
